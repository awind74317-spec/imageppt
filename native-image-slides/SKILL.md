# 純 AI 圖片式簡報

## 日常由 Luna 獨立完成

Web GPT 負責視覺理解、設計、分鏡提示詞、原生生圖與編修；Luna 負責批次、檔案、收件、核對及交付。不要按步驟拆出多個代理，不依賴 Sol／Astra 逐張核准；兩者只在指定排錯無效或未知情況下由使用者選擇救場。

只讀本入口及當次素材；續跑讀既有唯一狀態與當前批次，不全讀歷史或所有 references。使用者提供文稿和母版即可，不要求補分鏡、提示詞或手動附檔。若要求先找素材、起草文稿、選風格，先完成該階段；五種預覽可同包五圖。已有風格不重新探索。

依工作區核實裝置與資料邊界；技能安裝位置不是任務工作區，LOCAL_PROFILE依任務父層AGENTS的完整路徑定位，不在技能資料夾下猜相對路徑。技能不另授權敏感資料外送、登入或付費。只用授權的 Web GPT 原生生圖與編修，禁止程式疊字、PPT／Canva排版或改用其他引擎冒充。

## 固定順序

1. **一次確認。** 瀏覽器操作時讀 [素材傳遞與收件](references/browser-transfer.md)，沿用成功方法。指定標題與圖片特徵的可讀性確認合併進規劃回覆，不每批另發探測。同環境已確認 Space 嵌檔不可讀就直接附原始 MD／PNG。
2. **一次規劃。** 原文、母版與下方規劃要求送給 Web GPT，取得全案及自足的逐圖 Prompt，保存原文；Luna 不重寫視覺設計。遠端 `/mnt/data` 路徑和瀏覽器變數不算本機存檔。
3. **機械分批。** 讀 [任務檔與工具](references/run-format.md)。列完整 `expected_outputs`，用 `page_groups` 執行 `plan`。每包最多10張，同頁 final 與所有前置圖為不可拆的一組，按頁序填包，放不下就換包，不必湊滿。單頁超過10張退回 Web GPT 調整分鏡。已有合格圖沿用，只補缺件。
4. **先存再送。** 共通控制語只寫一次，逐圖原提示依製作順序組包。批次 MD 保存、讀回並記 SHA-256 後，將相同完整提示一次填入聊天框。送出後保留原檔，不用剪貼簿或重新組稿覆寫它。附件與提示就緒、即將點送出才記 `submitting`；看到實際使用者訊息後記 `sent` 及正式網址。一個新對話只送一包，包內可依序多次原生生成／編修，不逐張送第二輪。同頁須連續完成 `final → step02 → step01`，再開始下一頁；不可先生成多頁 final 後再跨回前頁倒拆。
5. **整批收件。** 同一 Luna 持有生產分頁，按瀏覽器指引等待。以批次完成、需修圖或受阻為工作節點，不逐張向別的代理報到。回覆結束後按實際內容核對頁次、階段，再下載原圖，不能只靠輪播序號。
6. **一次核對、只修錯圖。** 依下方品檢逐張看圖；小錯新開乾淨修圖對話，只帶唯一實際來源和單一修改。明記修圖替代的 `target`，錯圖不交付。正常製作不為測試而刻意修圖。
7. **集中交付。** 最後集中寫一次問題與耗用紀錄，`check`、`preflight` 後只封裝一次正式全案包；容量超限按預檢頁組另封裝小包。原始母版留素材區，不必納入PNG成品包。依 `space` 輸出的五欄清單與預覽更新，依 [固定 Space 排版](references/space-layout.md) 更新使用者指定的既有 Page；沒有指定時自行建立本案獨立素材入口，不要求使用者先提供 Page ID，測試案不得覆寫舊案頁面。入口建一次，按批更新，結案集中核對；每張只上傳一次，同一引用用於表格、檔名與預覽。不要逐張重改／重讀整頁。

## Web GPT 規劃與生成要求

- 保留正式內容的語意及關鍵資訊，允許同義改寫、語序／標點差異與不失原意的精簡，不要求逐字相同；講者備註不上圖。母版只取視覺語言，不抄其文字、頁碼。原文已有英文可保留；禁止新增沒有依據的標語、Logo、QR code、聯絡方式、價格或成效。
- 自行決定各頁形式、固定區域、預留空間及揭露層數，不固定每頁三張。輸出正式上圖文字、逐圖提示、檔名、來源、製作／播放順序及頁組，讓 Luna 直接保存與機械分批。
- 完整圖提示帶全部正式文字與設計；倒拆提示聚焦唯一來源、刪改項、原位保留項及該階段文字要求，不每張複製整份技能。
- 批次提示附唯一編號、檔名與製作序號清單，要求按序各完成一次；不得把同一頁的重複圖當成下一項。結束逐項列實際產物與缺件。張數不足先核對原回覆，確認漏件才另包補最小缺件，同頁剩餘漸進圖保持一組，附真正來源。這是降低漏件的提示改善，尚不保證模型一次全數完成。
- 每個圖片檔是一張完整投影片；同包可輸出多張獨立圖片，禁止多格拼貼。「一檔一頁」不是「一個對話只生一張」。
- 包內同頁依 `final → step02 → step01` 製作，每一步真正編修前一步實際產物，不文字重畫，不全部回引 final。先自檢 final；若明顯不合格，停該頁倒拆並指出錯誤，可繼續不依賴它的頁。
- 同頁鏈有缺件時，補件包只處理該頁：附上唯一最後一張有效實際來源圖，並在同一新對話依序完成尚缺的後續階段；第二階段的輸出必須成為第一階段的來源。若只缺一階段，就只要求一個輸出。不得同包混入另一頁來源或要求拼版。
- 刪除只補回原區域背景，其餘位置、尺寸、字級、固定文字與裝飾不變，不置中、放大、重排。結束列輸出對照與自檢結果；口頭聲稱不代替看圖。

## 六項品檢

1. 與文稿語意及關鍵資訊一致即可，不逐字比對；同義改寫、語序、標點或不失原意的精簡可通過。數字、名稱、條件、否定、責任及功能承諾不可改變；不能漏掉會影響理解的資訊或新增無依據的主張。僅措辭不同不得觸發修圖。
2. 一檔一張完整頁面，可辨讀，未裁切、非拼圖。
3. final 包含該頁全部正式內容。
4. 前置圖應刪的整組內容及連線確實消失，step01不能殘留第二站。
5. 相鄰階段保留元素的位置、大小與意思穩定；不影響閱讀的文字細微差異可接受，仍要求編修保留原區塊。播放 `step01 → step02 → final`，與製作順序分開。
6. 本機原圖存在，PNG及來源雜湊正確；每張final／前置圖各自目視後記 `qa_passed` 及簡短 `qa_note`，指出本張核對結果或具體錯誤，不能只記整批通過。

Web GPT自檢後，Luna做一次收件核對，不例行增加主模型全套重檢。OCR、檔案數、hash不能替代目視；介面未公開內部來源圖ID時，保留實際附件、提示與可見結果，明記內部來源不可直接驗證，不探索隱藏端點。僅因 Web GPT 沒有口頭確認來源，不判定圖片失敗；口頭聲稱也不算來源鏈證據。依實際提交的來源圖、提示的先後關係與逐張視覺品檢判定可見成果，內部來源不可查證就記為不可觀察。修正上游後須核對受影響下游，不能自動沿用舊鏈。

## 中斷與完成

`run.json` 是本案唯一逐批／逐圖狀態；不另建平行handoff或ledger。已有工作區長任務狀態只留目標、範圍及指向run的下一步，不重複逐圖資料。每批完成或受阻更新，不寫逐分鐘流水帳。

續跑先執行 `status`，核對當前批次、本機成果及原對話。`submitting`、`sent`或結果未知先查原對話，不能直接重送；已下載不重生，已上傳引用不重傳。

「無法載入對話／歷史」先確認有無本機結果，一次重新載入仍失敗就記平台受阻。短暫思考中不是失敗；不猜測頻繁對話是原因、不反覆開新對話、不自行排程。下一步固定留下「恢復後先查原對話，有結果先收件，確定無結果才補最小缺件」。結束回覆後不能宣稱仍在背景追蹤。

指定排錯仍失敗、同一品質修正仍不合格或未知情況，回報當前一步、已試方法、成果位置及最小後續動作，供使用者交 Sol／Astra 救場。真正資料／權限邊界依工作區規則停止。

完成需全數預定位置有合格圖、Space及封裝。缺件僅能明示部分交付，`pack --allow-partial`不把缺件變完成。每批在實際事件發生時記 `sent_at`、`generation_finished_at`、`collected_at`，不能事後猜填。記提示次數、已觀察圖數、重複圖、修圖／重工、主代理介入次數、批次耗時及最慢步驟；精確Token／費用不可讀就寫未知，帳號用量不能當單案消耗。

## 開發驗收限定

只有 `mode: acceptance` 才要求至少三代表頁、連續兩次倒拆、一次新對話修圖；使用者要求全案驗收仍做全案，不用代表頁替代。日常 `production` 不強制製造修圖。

更新後先驗機械行為，再由全新Luna只拿技能與最少素材驗獨立操作。離線演練不是Web GPT端到端驗收；平台恢復後可用保留的小補圖任務驗續跑與收件，完整批次另驗。需要追查歷史時才讀 [既有問題](references/observed-failures.md)。
