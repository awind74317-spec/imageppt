# 瀏覽器素材傳遞

適用於已授權將本批文稿、母版或上一張實際圖片提供給 Web GPT 的操作。只使用目前瀏覽器工具文件公開的介面；不操作登入憑證、背景端點或安全設定。

## 本機附件

先依 `cua_repl` 入口規則選取所需瀏覽器；例如已知對話網址時用 `const browser = await cua.getBrowser({url: chatUrl})`，已有選定 browser 就沿用。基本 `cua.getTab()` 只有簡化介面，不能據此判定沒有上傳／下載能力。若文件未顯示完整 API，呼叫一次 `await cua.rewriteDocumentation()`，讀到下方 **Other Browser APIs／API Reference**，不是只讀上半部基本 Tab 定義。

完整文件列出後，沿用 `browser`，依文件先 `await browser.nameSession("🖼️ 圖片簡報")`；從 `browser.tabs.list()` 找本次分頁並 `await browser.tabs.get(tabId)`。這個完整 Tab 才提供 `.playwright`，其定位器提供 `.downloadMedia()`；讀 `agent.documentation.get("file-uploads")` 後上傳。不要把基本 Tab 與完整 Tab 混用，也不自行載入其他客戶端。若讀完整文件後仍沒有必要方法，才記具體能力缺失並停止新增生圖。已確認同介面可用時不重複探測。

根據當前 DOM 或 accessibility 狀態打開可見「新增檔案／新增相片與檔案」選單，確認「從電腦上傳」控制項，再先等待檔案選取器、後點擊控制項。不要直接點隱藏 file input；本案該路徑已逾時：

```js
const chooserPromise = tab.playwright.waitForEvent("filechooser", {timeoutMs: 10000});
await tab.playwright.getByRole("button", {name: observedUploadButtonName, exact: true}).click();
const chooser = await chooserPromise;
if (files.length > 1 && !chooser.isMultiple()) throw new Error("此選取器只接受單檔，逐檔附加");
await chooser.setFiles(files); // 已核對、已授權的本機絕對路徑
```

附件完成條件：本批完整檔名、圖片縮圖可見、上傳進度消失且傳送按鈕可用。缺一項就停在附件步驟核對，不送空包。不要在只打開第一層加號選單時等待filechooser；先定位實際「從電腦上傳」項目，再開始等待及點擊。仍失敗時才讀工具提供的 Chrome 上傳排錯文件，依實際錯誤做一次有界修復；不繞過明確安全阻擋。Space Page 附加與原始 MD／PNG 附加是不同操作，前者不可讀時直接補後者。

## 多行提示詞

使用 `tab.playwright.getByRole("textbox", {name: observedComposerName}).fill(prompt)`，或工具文件明確保證不會送出的整段貼上介面。核對完整文字後，再點擊觀察到的傳送按鈕。不要使用逐鍵 `typeText` 傳多行稿；Enter 可能提前送出，留下後半段草稿。倒拆提示應明確為「移除」下一層，不能誤寫成「新增」。

素材可讀性在 Web GPT 規劃回覆中一次驗證：逐字回報一個指定標題及實際圖片特徵。附件標籤與上傳成功只證明傳遞，不代替內容確認。同一來源／環境已通過時不另發重複探測提示。

送出前先把完整實際提示存本機批次 MD，讀回並記 SHA-256；一次 `fill` 相同完整文字，不在送出時臨時重寫或添未保存文字。僅附 MD 加短指令的試驗未完成預定倒拆鏈，尚不取代此預設路徑。

本機檔案為提交來源，送出後不可反向覆寫。瀏覽器剪貼簿不等於 Windows 剪貼簿，禁止以 `Get-Clipboard` 接收瀏覽器文字，也不要手工拼接 Base64 搬運提示稿。規劃文字以工具公開的文字回傳取得後存檔、讀回；原始素材檔可直接附加，不以跨工具剪貼簿代替檔案傳遞。檔案若受損，保留受損／重建狀態與原對話，不把重建版冒充送出原檔。

附件與短文就緒、即將點傳送才記 `submitting`；確認使用者訊息已出現才改 `sent`，記錄正式網址。暫存的 `local-chatgpt` 網址不能當最終證據，待正式網址出現再更新。若確認失敗，保留未知狀態，先查現有分頁，不能再按傳送。

## 等待與分頁

- 一名 Luna、一個瀏覽器操作擁有者；沿用已選瀏覽器，不與主代理搶同一分頁。每包用新對話，留對話網址；已完成頁不拿來跑下一包。需交接時，在結束代理前對必要分頁呼叫工具公開的 `markHandoff()`，將瀏覽器／分頁 ID 留在對應 batch；接手後沿用，完成後關閉製作暫存分頁，成果頁用 `markDeliverable()` 保留。
- 初次送出後查一次「訊息是否已送、附件是否存在」。生圖期間以約45–60秒為下一次觀察間隔，每次等待不超過60秒；有新結果或使用者訊息可提早處理。不要每幾秒讀完整DOM或要求其他代理回報。
- 每次只讀判斷下一步所需的狀態：有無停止按鈕、生成節點數、回覆是否結束、實際錯誤。無變化不反覆印出整頁、截圖或工具說明；視覺核對才看圖。
- 「思考中」「正在生成」只是網頁狀態，不能當作下載或整案完成。沒有停止按鈕且長時間只有思考文字時，保存觀察後一次reload核對；不要只因超過65秒就重送。
- 完成回覆且輸出清單可核對後整批收件。張數不足先查整個既有回覆，不馬上另生；錯誤、受阻、缺件與進行中分開記錄。

## 已實證的原圖收件路徑

同環境的 PNG 收件直接走下列已成功的 Space 檔案預覽路徑，不先點聊天下載按鈕或等待 download 事件。這些舊路徑已多次逾時；換頁或換圖並非重試的新前提。

1. 從本批實際生成圖開啟「圖像預覽」，查看內容，對應頁次與階段；輪播索引只是定位，不是內容證據。
2. 點該圖的「檔案動作」→「在空間中開啟」。等檔案預覽真的顯示原圖，從當前 DOM 讀完整圖片名稱再定位；不要由上一張檔名猜序號或時間戳。切換圖像後亦先等所選圖片載入，再目視或下載，避免把尚未更新的預覽當成新圖。
3. 下載前，把正式輸出檔名、實際原圖名稱及已觀察到的 Space 預覽網址存入該 batch 的 `pending_download`；不猜網址。對目前頁面可見且已核對名稱的 `img` 使用文件公開的 `downloadMedia({timeoutMs:20000})`，取得實際本機路徑。只使用觀察到的元素，不猜 `/api/...` 網址、不抓token、不用背景fetch。
4. 以原始位元組複製到任務資料夾正式檔名，核對PNG與hash，再目視。不要用截圖替代原檔。保留來源hash供倒拆；修圖另存，不覆蓋來源圖。
收件完成條件：已取得實際本機路徑、PNG結構與hash通過且對應本張內容；以 `register` 保存逐圖紀錄，包括實際 `preview_url` 與 `original_filename`，再清除該 batch 的 `pending_download`，不手改artifacts陣列。

5. 下一張回原批次，核對新的實際內容再取檔。批次迴圈遇載入尚未完成，停在當前張重新觀察；不跳張、不默認下載成功、不重送生成。

原生下載按鈕／MD下載若等待事件逾時，先檢查本次操作後、符合已知檔名的新檔及其內容；本案完整施工稿曾事件逾時但檔案已落地。不要廣掃下載目錄或把遠端`/mnt/data`當本機檔案。原圖路徑不可用時只做一次有新前提的有界修復，仍失敗保留已生成對話與缺件狀態。

## 暫時異常與交接

同一對話出現「無法載入此 ChatGPT 對話／無法載入歷史記錄」，一次重新載入仍錯就停止原對話路徑。先查本機有無落地檔；尚缺原圖時，重開已觀察且已保存的 Space 預覽網址，確認完整圖片載入後，沿公開 `downloadMedia()` 收件。沒有已知預覽或仍不可讀時，可從既有圖像庫按已觀察檔名定位，逐張目視核對，不能以序號猜圖。原圖仍可取得不算整案受阻；上述一次有新前提的恢復仍失敗，才更新原任務狀態為 `blocked`，留下原網址、已存圖、缺件及下一個最小動作。不開重複生圖對話、不重送、不猜背景端點，也不推定限流原因。

下次恢復先開原對話檢查結果。沒有平台回覆、沒有圖，不代表提示沒有送出；在確認結果前不要重送。需要交接時只給當前批次檔案、已驗證方法及狀態，不搬整串歷史。
