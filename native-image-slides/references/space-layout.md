# 固定 Space 排版

沿用實跑形成的固定素材入口：document 版型、一般 Markdown、無額外區塊版面設定。此處保存可重複套用的結構，不必讀取其他人的舊案或下載舊案素材。

## 固定結構

原生頁面標題為「{本次主題} {頁碼範圍} 製作素材入口」，內文不重複一級標題。保持以下順序與標題：

1. `## 素材`：條列附件連結。依序為全案／本次交付原圖 ZIP（實際張數、容量）、小型測試 ZIP（有提供才列）、原始文稿、全案規劃／分鏡稿、逐圖提示詞與各頁任務包（旁附產稿對話）、共通製圖規則或結果紀錄（已有才列）。規則和詳細紀錄用附件，不在入口展開成長篇說明；不為湊齊項目另製無用文件。
2. `### 視覺母版`：位於素材區內，直接嵌入本次主參考圖，再依序嵌入實際有提供的補充母版。使用當次授權的參考素材，不能從排版範本複製舊案圖片或把頁面排版偏好當成所有簡報的固定美術風格。
3. `## 完成清單（{本次規劃交付張數} 張）`：先以一句話寫已完成、待製作、待修正張數；接五欄表格，欄名與順序固定為 `頁次 | 分鏡 | 狀態 | 完成 | 原圖`。一張交付圖一列，頁碼數字遞增，同頁依播放順序排列，final 放在同頁前置分鏡之後。附屬案例卡依全案規劃接在該頁後。
4. `## 圖檔（依頁次順序）`：與清單同序逐張展示，每張先列可開啟的完整 PNG 檔名連結，再緊接同一原圖的大圖預覽。不能只有縮圖拼貼、只列 final 或只給 ZIP。相關生圖／修圖對話連結可放在圖檔區末尾。

## 內容與狀態

- 只固定排版；課程名稱、頁碼、張數、容量、分鏡數、檔名、圖片與連結全部來自本次工作，不沿用範本的「61 張／全部完成」。
- 代表頁驗收要明寫「本次驗收交付」，不把全案規劃的頁數說成全部完成。張數以本次規劃交付圖片為準，實驗中間圖不混入正式清單。
- `完成` 與 `☑` 僅用於已保存原圖且品檢通過者。其他列寫實際狀態（待製作／待品檢／待修正／受阻），使用 `☐`。已有待修正圖片可列原圖並顯示預覽，但不能勾選完成。
- 沒有的附件不造連結：尚未產生的必要成果寫「待產出」，未提供的小型 ZIP 等選用項目不列。未完成圖片不插入破圖佔位。
- PNG 的表格連結、檔名連結、圖片預覽使用同一真實上傳引用。使用工具回傳的 `library-file:` 或 `project-file:` 等支援引用；不寫本機路徑或捏造 ID，不擅自改寫原圖。
- 修圖完成且品檢通過後，更新該分鏡列與預覽為採用版本；舊版本保留於執行紀錄，不在正式清單重複計數。

## 填寫樣式

以下是結構示意，花括號必須換成實際資料及工具回傳引用，不能原樣發布。每個有圖的清單列都要有一組「連結＋預覽」。

```markdown
## 素材

- [本次交付 {N} 張原圖 ZIP（約 {大小}）]({ZIP引用})
- [原始文稿]({文稿引用})
- [全案規劃與分鏡稿]({規劃引用})
- [逐圖提示詞與任務包]({提示詞引用}) · [產稿對話]({對話網址})

### 視覺母版

![主母版]({母版引用})

## 完成清單（{N} 張）

本次交付共 {N} 張；已完成 {完成數} 張，待製作 {待製作數} 張，待修正 {待修正數} 張。每列可開啟原圖，下方依頁次保留圖片預覽。

| 頁次 | 分鏡 | 狀態 | 完成 | 原圖 |
|---|---|---|---|---|
| P1 | P01-step01 | 完成 | ☑ | [PNG]({前置圖引用}) |
| P1 | P01-final | 待修正 | ☐ | [PNG]({final引用}) |

## 圖檔（依頁次順序）

- [P01-step01.png]({前置圖引用})

![P01-step01.png]({前置圖引用})

- [P01-final.png]({final引用})

![P01-final.png]({final引用})
```

## 最小核對

頁面文字與附件優先使用 Pages 連接器，依其 write-page 技能讀取目前工具規格；不是所有操作都走瀏覽器。未指定既有 Page 時用 `create_page` 建立本案私人入口，並保留回傳 ID。用 `write_page_reference` 上傳本機原檔，確認 `file_access_confirmed=true`、回傳 sha256 與本機一致後才保存 reference。不得把畫面內的 file_id 加上 `library-file:` 前綴自行造引用；看見檔案識別碼不代表該 Page 能讀檔。

取得 `read_page` 的目前區塊與更新保護值後，用 `edit_page` 集中寫入完整 Markdown；原檔上傳不會自動插入預覽。瀏覽器只負責實際版面核對，或連接器未提供的操作。避免逐列／逐格用網頁編輯器施工。

若 Page 內容讀取回覆可重試的 `page_freshness_unavailable`，一次有界重讀仍失敗，不反覆換參數。對**完全由本案產生、沒有他人內容的素材入口**，可用已保存的完整 Markdown 做一次瀏覽器貼上：`tab.clipboard.writeText(markdown)`，點目前 DOM 的「頁面文件」編輯區，依序 `ControlOrMeta+Home`、`ControlOrMeta+A`、`ControlOrMeta+V`。必須從正文開頭選取整份文件，不能停在表格儲存格；不要用 `fill`、逐鍵 `typeText` 或逐列輸入富文字表格。這是瀏覽器自己的剪貼簿，不透過 Windows `Get-Clipboard`。有他人內容或範圍不清時不整頁覆寫。

貼上後等圖片載入，再重新開啟同頁確認保存；核對標題順序、五欄、每圖一列、圖片可見。連接器仍不可讀時明記使用瀏覽器讀回，不宣稱連接器成功。長頁以可見區域確認表格與圖片，不例行做容易逾時的全頁長截圖。

電腦版已載入圖片不代表手機 App 已能顯示，縮窄網頁也不等於手機 App 驗收。使用者提供手機「無法在此顯示這個附件」證據時，先讀取一張現有原圖確認引用可讀與圖片格式，不重傳／重生整批；只對一張圖片試支援的顯示方式，取得實際手機結果後才批次套用。沒有手機核對證據時只記「電腦版通過，手機未驗」，不得聲稱跨裝置交付完成。若原圖可讀而手機仍不顯示，記錄為手機呈現受阻、根因未確認，保留原圖連結與ZIP，不用猜測的語法或反覆上傳修平台問題。

素材入口先建立一次，生產中以整批完成為更新節點；結案集中填入清單、預覽與ZIP。以run.json的expected_outputs／selected_files為同一來源，避免另手算一份進度。每張PNG上傳一次即把回傳引用留在對應artifact，表格、檔名、預覽共用該引用；已有引用不重傳。

工具若有單檔容量上限，先按本次已知上限及實際ZIP大小決定是否分包，不能靠反覆上傳失敗試探。分包只改封裝，不重做圖片；每包標清涵蓋頁次與缺件，全案本機ZIP可保留。不要為逐張更新反覆重新封裝。

用 `space` 從唯一run產生五欄清單和圖檔區；沒有 `page_reference` 先上傳並把真實回傳引用保存於artifact，再重新產生。腳本只產草稿，不會上傳或發布。若同頁保存多個版本，最新版本入口放前面並指明舊版，保留歷史。

更新後讀回四個標題的順序、表格欄名、張數與完成狀態；逐列確認圖片引用和下方預覽一致，並確認沒有殘留佔位文字。首次建立或整體重排時，以實際瀏覽器確認母版、表格與原圖預覽可見。一般 Web GPT 無法讀取 Page 附件時，維持此入口排版，改用對話直接附件施工，不另造第二套入口。
